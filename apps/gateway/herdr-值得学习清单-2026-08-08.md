# herdr 值得学习的点（优先级清单）

日期：2026-08-08

对比对象：TmuxGo（浏览器里的 tmux 工作台，Node/TS gateway + Next.js 前端）
分析对象：herdr（Rust 写的终端级 AI coding agent 工作台，`herdrdev/herdr`，官网 https://herdr.dev）

## P0：最值得学

### 1. Agent 控制面打通

herdr 最核心的设计是 agent-native：`herdr` CLI 和 socket API 是同一套接口，agent 在自己 pane 里就能开新 pane、跑命令、读输出、等另一个 agent 阻塞。

TmuxGo 现在有 agent 状态检测（`apps/gateway/src/lib/agent-state.ts`）和 agent 连 gateway 的桥（`apps/gateway/src/agent-manager.ts`），但缺“agent 作为操作者”的协议面。建议：

- 定义 versioned 的 socket/HTTP 协议 + 官方 skill 文件，注入 `TMUXGO_ENV=1` 守卫。
- 支持 `pane split` / `pane read` / `agent wait` 这类操作。
- `agent.wait` 采用服务端持有、事件驱动、钉住当前 pane 占用者的语义，防止替换进程满足等待。TmuxGo 目前没有 wait 原语，这是多 agent 编排最值得抄的一块。

### 2. 语义状态和展示元数据分离 + workspace 级 rollup

herdr 明确区分：

- semantic state：影响 wait / notification / attention。
- display metadata：title / state_labels / tokens，带 TTL、source-scoped、seq 去乱序。

TmuxGo 的 `AgentPaneState` 是消息、phase、status 混在一个 record 里。建议：

- 引入 token 补丁 + TTL 的上报模型，展示层只消费展示字段。
- UI 增加 workspace/tab 级 rollup（blocked/done 计数），一眼看到哪个项目需要人。
- 这是纯展示层和编排层的边界问题，不动架构就能做。

## P1：值得做

### 3. Session 恢复分层模型

herdr 的恢复矩阵值得整套抄进设计文档：

- detach / reattach
- live handoff（更新时转移 live pane）
- native agent session restore（`codex resume <id>` / `claude --resume <id>`）
- pane history replay（默认关闭，带 secrets 警告）
- snapshot restore（恢复形状，不保留进程）

TmuxGo 已经记录了 `agentSessionId`，缺的是：

- 服务重启后自动 resume agent 会话。
- 默认关闭、带 secrets 警告的 pane 历史。

这条和“跨设备接力”的主线叙事直接契合。

### 4. 声明式布局 export/apply

herdr 的 portable BSP tree（`pane/split/ratio/label/cwd/command/env`）可以导出、分享、重建，且不碰 live PTY。

TmuxGo 有会话模板但不可分享、不可做运行时恢复。把模板升级成可导入导出的布局 JSON，低成本高回报。

### 5. 轻量插件面

herdr 核心保持精简，插件是 manifest 声明（actions / events / panes / link handlers），命令通过 `HERDR_BIN_PATH` 回调 CLI，没有独立 SDK。

TmuxGo 是单体，`plugins/` 目前只是放了个 `vscode-git-graph` 组件。如果要做扩展，先从“本地 manifest + 事件 hook + action 菜单”的小切口开始，不要一上来做 marketplace。

## P2：可以借鉴

### 6. 协议工程纪律

- `api schema --json` 自动导出 JSON Schema。
- 协议版本兼容，客户端优雅处理未知字段。
- `session.snapshot` 全量引导 + 事件订阅增量更新。

对第三方客户端和 agent 友好，长期降低集成成本。

### 7. Git worktree 一等公民

`worktree.create/open/remove` 带 provenance，删 worktree 不删分支，正好接 TmuxGo 已有的 Git workbench。

### 8. 通知 API 的工程细节

title/body 清洗截断、rate limit、delivery 可配置（herdr/system/off）、sound。TmuxGo 已有 agent 通知，补齐这些边界就够。

### 9. 文档即产品

concepts / socket-api / config-reference 全套双语 + schema 自动生成。TmuxGo 缺的是“给 agent 和第三方看的协议参考”。

## 不建议学

- 单 Rust 二进制、无 electron：TmuxGo 定位就是浏览器工作台，换栈不符合产品方向。
- live handoff、鼠标原生 UI、系统级更新链：浏览器端天然鼠标优先，systemd/launchd 重启已够用。

## 总结

P0 是“让 agent 反客为主操作工作台 + 状态语义分层”，这是 herdr 和普通 tmux 前端拉开差距的本质；P1 是围绕恢复、布局、扩展的工程化；P2 是协议和工程细节。
