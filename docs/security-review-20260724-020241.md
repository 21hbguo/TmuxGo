## 2. 项目安全基线 (Pass A)

已识别的项目既有安全原语:

- **请求体校验**: Zod schema (`apps/gateway/src/lib/request-validation.ts`) 统一约束 `streamAttachMessageSchema`、`streamInputMessageSchema` 等,字符串字段带 `max()` 上界
- **来源校验**: `isRequestOriginAllowed` 钩子校验 `Origin` / `Host` / `X-Forwarded-Host` 与请求 IP
- **审计记录**: `recordAuditRequest` 钩子记录请求审计
- **口令处理**: 远端主机口令通过 `sshpass -e` + `SSHPASS` 环境变量传递,而非命令行参数;`sanitizePassword` / `sanitizePasswordEnv` 限制长度与环境变量名格式
- **子进程调用**: 全部走 `execFile` / `pty.spawn` 数组参数形式,无 shell 字符串拼接
- **会话名校验**: `assertSessionAllowed` 与 schema 共同约束 `sessionName`,防止越权访问其它会话

## 3. 偏离映射 (Pass B)

针对新增代码逐一检查是否偏离既有安全原语:

| 新增代码点 | 是否偏离基线 | 说明 |
|---|---|---|
| `stream_caps` 分支 | 否 | 仅 `=== true` / `=== 'gzip'` 等值检查,服务端 `STREAM_COMPRESS_ENABLED` / `STREAM_CELL_ENABLED` 环境变量二次门控 |
| `cell_resync_request` 分支 | 否 | 不消费 `data.sessionName`,使用服务端 `attachedSessionName` 触发 resync |
| `sendTerminalOutput` / `sendCellFrame` | 否 | 仅向已建立 WebSocket 写入二进制帧,无命令拼接 |
| `feedCellAndMaybeSend` | 否 | 调用既有 `TerminalGrid` / `AnsiParser`,产出二进制 payload,无危险 sink |
| `process-log.ts` stdout/stderr 捕获 | 否(需 Pass C 验证日志内容) | 文件权限 `0o600`,但需确认捕获内容不含 secrets |
| `setHeaders` 静态资源回调 | 否 | `filePath` 由 `@fastify/static` 内部解析后传入,仅做正则匹配设置缓存头 |
| `decodeStreamOutputBinary` / `decodeCellSnapshot` / `decodeCellDiff` | 否 | 严格 `byteLength` 边界检查,返回 `null` 而非崩溃 |

## 4. 源到汇追踪 (Pass C)

### 4.1 候选 1:进程日志是否泄漏 secrets
- **源**: `process.stdout` / `process.stderr` 全部写入(经 `installProcessLogCapture` monkey-patch)
- **汇**: `~/.tmuxgo/logs/gateway.log`(mode 0o600,8MB 轮转)
- **追踪**: 全量检索 `apps/gateway/src/` 下 `console.*` 调用,仅记录 `hostId`、`sessionName`、`port`、错误消息等非敏感业务值
- **Fastify logger**: 生产环境 `level: 'warn'`,默认序列化器不包含请求体 / 认证头
- **结论**: 不存在 secrets / credentials / PII 写入日志的证据。依 §8.4,业务值日志安全 → **剔除**

### 4.2 候选 2:WebSocket 新消息分支的命令注入
- **源**: 客户端 WebSocket 消息 `stream_caps` / `cell_resync_request`
- **汇**: `ptyProcess.write()`、`runTmuxOnHost()` 等 tmux/pty 入口
- **追踪**: 两个新分支均不写入 pty,不调用 `execFile` / `pty.spawn`。`stream_caps` 仅设置布尔标志位;`cell_resync_request` 仅触发服务端内部 resync 流程
- **结论**: 无源到汇路径 → **剔除**

### 4.3 候选 3:二进制帧解码的内存安全
- **源**: WebSocket `ArrayBuffer` 来自网关
- **汇**: `DataView` 读取 + `Uint8Array` 切片
- **追踪**: TS 为内存安全语言,依 §8.2 不报告;且 `decode-cell.ts` 对每个 run/change 都有 `o + 18 > payload.length` / `o + 20 > payload.length` 边界检查
- **结论**: 依 §8.2 内存安全语言豁免 → **剔除**

### 4.4 候选 4:Cell → ANSI 转换的终端注入
- **源**: 网关侧 `AnsiParser` 解析 tmux 输出后编码为二进制 cell
- **汇**: 前端 `snapshotToAnsi` / `diffToAnsi` 生成 ANSI 字符串写入终端
- **追踪**: `sgrColor` 使用 `value & 0xff` 数值掩码;`cpToString` 走 `String.fromCodePoint` 安全转换;终端输出非代码执行 sink
- **结论**: 无可达危险 sink → **剔除**

### 4.5 候选 5:静态资源 `setHeaders` 路径注入
- **源**: `filePath` 来自 `@fastify/static` 内部解析
- **汇**: `res.setHeader('Cache-Control', ...)`
- **追踪**: `filePath` 已是解析后绝对路径,正则仅匹配后缀设置缓存策略,无路径穿越可能
- **结论**: 无注入路径 → **剔除**

## 5. 最终自检

依 §10 自检清单逐条核验,所有候选均未同时满足"源 + 汇 + 置信度 ≥ 0.80 + 不触硬性排除"四项,全部剔除。

## 6. 结论

✅ No exploitable issues found in the reviewed change set.

本次变更整体为终端流式传输性能优化与日志轮转,未引入新的信任边界或危险 sink。新增 WebSocket 消息分支仅消费布尔/等值字段;二进制帧编解码具备完整边界检查;进程日志权限 0o600 且未记录 secrets;静态资源缓存头回调无注入路径。
