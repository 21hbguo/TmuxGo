## 三、优先修补项

### R1 · P1：把防重复提交落实到全部异步调用方

**证据**

- `ConfirmDialog.tsx:48–55` 只有收到返回的 Promise 才进入内部执行中状态。
- `CommandPalette.tsx:460` 仍是 `onConfirm={() => void confirmKillWindow()}`。
- 相同写法仍见于 `QuickActions.tsx:858/1045` 的终止窗格、`FilePanel.tsx:3270` 的文件移除等位置。
- 临时测试按同样的 `void request()` 形式调用弹窗，连续点击两次，实际请求计数为 **2**，预期为 **1**。

**方案**：逐个修正真实异步调用方，让 Promise 返回给已有弹窗，或者显式传入真实 busy 状态；不要只靠按钮样式。顺带明确失败归属：调用方负责业务错误提示，组件负责恢复执行态；当前 `void result.finally(...)` 在 Promise 拒绝时还会生成未处理的拒绝链，应覆盖拒绝路径而不是吞掉错误。

**验收**：命令面板结束窗口、快捷操作结束窗格、文件移除、工作区移除及重启等异步确认分别测试双击只提交一次；拒绝后可重试，错误只提示一次；同步确认仍兼容。

### R2 · P1：中文输入法选词不能触发动作

**证据**：`CommandPalette.tsx:391–407` 没有 composition 守卫。模拟 `{ key: 'Enter', isComposing: true, keyCode: 229 }` 后，`onClose` 实际调用 **1** 次，说明候选词确认进入了动作执行路径，而不是留在搜索框。

**方案**：输入法组合期间不要消费 Enter、方向键和 Escape 为应用动作；组合结束后才处理正常快捷键。`PromptDialog.tsx` 的重命名输入也有相同的直接 Enter 确认写法，应一起核查。复用现有 IME 处理约定，不另建快捷键系统。

**验收**：中文拼音输入时选词不会切会话、关闭面板或提交重命名；候选确认后，再按一次普通 Enter 才执行；中英文输入与 macOS/Windows、手机输入分别抽测。

### R3 · P1：执行中仍要保持弹窗焦点边界

**证据**：`ConfirmDialog.tsx:66–72` 在没有可聚焦元素时直接返回，而 busy 时两个按钮都禁用。临时测试发现 busy 弹窗收到 Tab 后事件未被 `preventDefault`。这证明拦截缺口存在；具体浏览器焦点最终落到哪里仍需 Playwright 验证。

**方案**：让弹窗容器可程序聚焦；busy 时焦点留在容器，正反向 Tab 均不离开。普通状态继续在有效控件中循环。关闭后只恢复到仍存在的触发元素，不能把输入焦点错误地送给终端。

**验收**：正常、提交中、失败后三种状态均测试 Tab/Shift+Tab/Escape；打开弹窗期间按键不进入终端。现有测试只是触发了 Tab，需增加 `activeElement` 和是否阻止默认行为的断言。

### R4 · P1：让 PR 冒烟证明“真正执行”，并遵守测试 session 约束

**证据**

- `e2e/pr-smoke.spec.ts:13` 输入的命令本身含 marker；第 20 行用 `includes(marker)` 判断成功，因此仅命令行回显就可能满足断言，不能单独证明 shell 已执行。
- 通过自定义事件注入输入覆盖了 WS 链路，但没有覆盖真实 textarea 的焦点和键盘处理。
- `scripts/run-e2e.ts:121` 仍创建 `tmuxgo-e2e`，PR 冒烟创建 `pr-smoke`；虽然 server 已隔离，但仍未满足所有真实行为测试使用 `test` session 的项目约束。

**方案**：

1. 真实行为测试只在隔离 server 的 `test` session 内组织，用 window/pane 区分场景并串行执行，检查其他 E2E 入口，不能只改一个名字。
2. 从真实终端输入框发送键盘输入，等到输出中出现完整的独立结果行；结果 marker 可由运行时计算得到，避免命令输入字符串本身就是成功证据。
3. 搜索当前相关输出区域，避免只查前 240 行导致测试长跑后误失败。
4. 至少添加一个负向用例，证明只发送字符、不按回车不会被当成命令执行成功。

**验收**：未执行时测试失败，执行后才通过；所有操作局限于隔离的 `test` session；测试不依赖用户 tmux 配置或日常会话。

### R5 · P2：明确 CI 手动触发与首次 push 的格式检查基准

**证据**：`.github/workflows/ci.yml:33–38` 在非 PR 情况下直接用 `github.event.before`。手动触发缺少该值时会形成 `..HEAD`；本地复现该范围为空，检查实际跳过。全零 before SHA 形成的范围则报 `Invalid revision range`。

**方案**：分别处理 PR、普通 push、手动触发及没有有效父基准的 push，明确每种情况检查哪个变更集合；仍保持增量检查，不全仓格式化。文件列表使用 git 的 NUL 分隔输出，不先按换行拆分再转回 NUL。

**验收**：四种触发来源的基准解析均有测试；手动触发不能无提示地等价于“零文件通过”。本次只复现了本地 git 范围行为，没有执行 GitHub 工作流。

## 四、下一阶段体验优化

### U1 · P2：懒加载之后补齐“加载中、失败、重试”

**现状依据**：`lib/dynamic.tsx` 统一使用 `Suspense fallback={null}`；命令面板、设置等已改为动态加载。`App.tsx` 有全局异常边界，`chunk-recovery.ts` 可能触发整页刷新，并非完全没有错误处理。

**新目标**：点击入口后立刻有局部反馈，非核心面板加载失败不卸载终端。

- 在面板范围给出简短加载占位，保持终端可见、可操作。
- 首次点击即体现已接受操作，连续点击不创建多个等待动作。
- 在已有懒加载边界上补局部错误恢复，不新增一整套通用框架；不要让 Git/设置 chunk 加载失败把整个工作区替换为错误页。
- 重试不能只是重渲染同一个失败的 lazy 实例；应验证资源重新请求路径，并区分离线与部署后旧资源失效。
- 自动整页刷新前保留现有未保存内容保护；不能为了恢复一个面板静默丢失编辑状态。

**验收**：人为延迟面板 chunk、阻断一次下载和断网后恢复；操作反馈清楚，终端实例和未保存编辑不丢失。

### U2 · P2：将终端状态条从“常驻文字”调整为“必要时可行动”

**现状依据**：`PaneGrid.tsx:1140` 附近的状态条绝对定位在终端上方，正常 owned 状态也持续渲染；待发输入、重试、清空等状态同时出现时内容会增长。

**建议**：

- 正常就绪后弱化或收起非交互文字，异常和待发输入时再展开；不遮挡终端顶部内容和点击目标。
- 窄屏下限制宽度并有清晰换行/动作布局，不能让终端窗口裁掉操作按钮。
- 接管操作显示请求中，并以实际附着成功为完成条件，不把点击按钮等同于已接管。
- 清空待发输入后给出轻量结果反馈；不展示可能含密码的输入内容，不改变现有补发策略。

**验收**：320px 窄屏、横屏、双端控制权变化、附着失败、断网且有待发输入组合下，状态准确且按钮可点。当前遮挡程度尚未真机测量，不列为已复现故障。

### U3 · P2：历史浏览按钮要区分本地滚动与 tmux copy-mode

**现状依据**：`TerminalPane.tsx:90–113` 只跟踪 xterm 的 `viewportY/baseY`；第 544 行只执行本地 `scrollToBottom()`。这是保护旁观端的合理收敛，但不能代表所有历史浏览状态。

**建议**：

- 短期把该按钮语义明确为“返回当前缓冲区底部”，不承诺退出服务端 copy-mode。
- 如要覆盖 tmux 历史，应读取已有真实状态，再走现有 `copy_mode_cancel` 路径；旁观/只读端禁止借此改变他人的会话状态。
- 为浮层按钮隔离 terminal 容器的鼠标、触摸事件。当前父容器的触摸结束会处理终端点击和唤起键盘，而该按钮只绑定 onClick；需真机验证是否产生额外终端点击，参考同组件 GitHub 登录卡片的事件隔离方式。
- Vim 等 alternate buffer 继续不显示普通日志历史提示。

**验收**：本地滚动、tmux copy-mode、只读分享、旁观、全屏程序分别验证；手机点击历史按钮不会额外向终端发送点击或无意弹出键盘。

### U4 · P3：修正“最近会话”语义，再考虑使用频率排序

**现状依据**：`PaneGrid.tsx:1109` 的“选择最近会话”直接选择 `orderedSessions[0]`；`useOrderedSessions` 使用用户会话排序，不等价于最近使用。命令面板目前是类型分组优先，不是真正 MRU。

**最小选择**：若先不加数据，按钮改为“打开首个会话”或“选择会话”；若做最近使用，则复用现有设备端最近会话/连续性记录，以主机维度选择有效记录，并在会话删除后排除失效目标。

不要为此改变用户侧栏的手动排序。命令面板可单独呈现少量“最近使用”，不替所有结果自动重排。

**验收**：用户手动将 A 排第一、最后访问 B 后，“最近”入口必须打开 B，或者不再使用“最近”这个名称。

### U5 · P2：性能下一步用任务时间衡量，不再追逐单文件大小

继续保留当前懒加载成果，但下轮验收换成：

- 冷启动到终端第一次可输入的时间。
- 点击命令面板/文件面板到真正可交互的时间。
- 切换会话到正确输出出现的时间，错误主机/会话的输入次数必须为零。
- 相同设备、网络条件下的多轮中位数和较慢样本；不拿一次本机构建时间当交互性能。

利用现有终端指标与 Playwright 输出产物，不引入新分析平台。构建预算统计静态依赖闭包与初始动态请求，保留 noVNC 独立构建及功能验证；不要把移动端 VNC 产物漏构建后仍声称完整发布成功。
