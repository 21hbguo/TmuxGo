# TmuxGo 体验与交互优化建议

- 时间：2026-09-23 01:16:24（Asia/Shanghai）。
- 范围：基于当前组件、状态管理和交互事件实现的源码评审；未进行浏览器操作或移动设备实测。
- 与工程优化的区别：重点不是让代码更整洁，而是让用户知道当前状态、操作结果和下一步。
- 本次仅新增文档，不修改运行逻辑，不重启服务。下列方案为交互提案，不代表已验证的用户行为结论。

## 一、总体方向

建议围绕三个问题改进：

1. **现在能不能操作？** 区分连接成功、终端就绪、旁观状态和输入待发送。
2. **怎样更快到达目标？** 缩短找会话、切窗口、打开文件和手机输入的路径。
3. **操作失败或误操作后怎么办？** 提供明确后果、执行中反馈和可用的恢复入口。

已有命令面板、会话连续性、多行粘贴确认、文件回收站与撤销、编辑器未保存提示、任务中心，不建议重新做一套同类功能。

## 二、按用户感知收益排序

| 顺序 | 建议                             | 用户感知                             | 建议规模     |
| ---- | -------------------------------- | ------------------------------------ | ------------ |
| 1    | 显示终端控制权与可输入状态       | 不再把旁观或附着中误认为键盘失灵     | 小至中       |
| 2    | 说明重连期间输入的去向           | 不再担心命令是否丢失、是否会延迟执行 | 中           |
| 3    | 把命令面板做成真正顺手的切换入口 | 找会话、窗口和动作更快               | 小至中       |
| 4    | 优化手机底栏的信息层级           | 常用操作更容易点，设置入口更容易认   | 小至中       |
| 5    | 改进危险操作确认与弹窗焦点       | 降低误终止、重复提交和键盘误输入     | 小至中       |
| 6    | 让错误提示能指向下一步           | 失败后不需要猜原因、重新找入口       | 小           |
| 7    | 明确历史浏览与实时输出状态       | 看日志时不担心被新输出打断或错过更新 | 中，需先验证 |
| 8    | 给空页面和目录跟随提供明确动作   | 第一次使用或切换场景时不迷路         | 小           |

### 1. 终端控制权：让“看得到但不能输入”有明确解释

**当前依据**：`PaneGrid.tsx` 已有 `ownershipLost`、`attachPassive`、`exclusive`，会在其他端获得独占权后降级为旁观。当前终端渲染区域没有相应的控制权操作提示；移动端连接提示主要呈现 `connectionStatus`。

**建议交互**：在终端上沿用小型状态条区分：

- `可输入 · 本机控制`：低干扰展示，正常状态可以弱化。
- `旁观中 · 当前控制权不在本页`：提供明确的“接管操作”入口。
- `正在附着终端…`：不要等同于“连接已就绪”。
- 真正的只读分享显示 `只读分享`，不能出现接管按钮。

只展示系统已知的信息，没有设备身份信息时不要写“另一台手机正在操作”。第一阶段只改善状态表达；新增接管按钮时必须复用已有授权与仲裁流程，不绕过权限、不自动抢占，不改变现有自动恢复策略。

**验收场景**：两端打开同一测试会话，失去控制的一端能解释原因并找到合法恢复入口；切回窗口不会触发持续互抢。

### 2. 重连与待发输入：不要只显示一个“重连中”

**当前依据**：`useWebSocket.ts` 已有自动重连；`PaneGrid.tsx` 的 `handleInput` 在无法直接发送时将输入放入队列，连接恢复后调用 `flushInputQueue`。因此不能把当前行为描述为“离线输入必然丢失”。

**建议交互**：

- 短暂波动不连续弹 Toast，保留现有画面，在终端上方显示非遮挡状态。
- 持续中断时显示 `连接中断，正在重连；存在待发送输入`，并说明现有自动补发行为。
- 提供“立即重试”“清空待发输入”这样的明确动作，而不是笼统的“刷新页面”。
- 页面中区分“网络恢复”和“当前会话已经可输入”，不能仅凭 WebSocket 打开就显示全部恢复。

若后续要让长时间离线输入在恢复前再次确认，应单独作为行为变更评审：不能把所有终端输入当作可编辑 shell 命令，尤其是 Vim、交互程序和包含回车/控制键的输入。第一阶段不擅自改变排队、补发和容量策略，只改善可见性与明确取消能力。

**验收场景**：断网时键入、粘贴并按回车，恢复前后用户能判断哪些输入仍在等待；点击清空后绝不补发。测试同时覆盖 shell 和交互程序。

### 3. 命令面板：先做好搜索语义和键盘导航

**当前依据**：`CommandPalette.tsx` 已支持主机、当前主机的会话、当前会话的窗口及动作搜索，但主要按 `includes` 过滤；分屏动作按英文 `split horizontal/vertical` 匹配，而标题会翻译。上下键更新选中索引，没有看到对应条目随选中自动滚动的处理。

**建议顺序**：

1. 中文标题、英文动作和少量同义词都能命中，例如“分屏”“split”“水平”。先用简单关键词，不引入搜索库。
2. 选中项始终滚动到可见区域；输入查询时保持确定的首选项。
3. 空查询优先展示最近使用的会话、窗口，再展示操作，不把危险动作排在默认第一项。
4. 显示会话所属主机和窗口归属，避免同名结果混淆。
5. 快捷键提示跟随实际绑定及平台显示，避免面板里写着固定 `Cmd`、用户却在 Windows/Linux 上操作。

跨主机搜索是后续选项，不应为了搜索每次并发连接所有主机；第一阶段利用已有数据即可。

**验收场景**：中文输入“分屏”能找到对应动作；连续按方向键时选中项不离开视野；从面板完成切换后，可直接继续终端输入且不会把搜索文本发入终端。

### 4. 手机底栏：先修“入口看不懂”，再做减法

**当前依据**：`MobileNav.tsx` 用七列同时展示会话、窗口、窗格、文件、Git、桌面和设置。设置按钮的可见文字使用连接状态或延迟，如 `...`、延迟数值，而不是设置名称。

**最小改进**：

- 设置入口始终显示“设置”，连接状态单独展示，不能用数字替代操作名称。
- 所有打开的面板有一致的选中反馈；当前 Git 已有 `aria-current` 和选中样式，可作为现有参考。
- 键盘打开时优先保留输入辅助动作，不新增第二排常驻工具栏。

**进一步试验**：窄屏提供“会话 / 窗口 / 文件 / 更多”等精简布局，将窗格、Git、桌面、设置放入更多面板；保留原七项布局或快捷入口，避免让重度 Git、桌面用户被迫多点一次。先比较日常任务的点击次数与误触，再决定默认布局，不一次性改掉所有人的使用习惯。

**验收场景**：窄屏、横屏、键盘展开时入口仍可辨认；打开文件、切会话、返回终端不会无故唤起或收起键盘。

### 5. 危险操作：明确“结束进程”，不只是“删除一项”

**当前依据**：`SessionPanel.tsx` 已使用确认弹窗，中文提示写明不可撤销；但主要呈现会话名称或批量数量。`ConfirmDialog.tsx` 没有执行中状态、重复确认限制或弹窗语义，`ModalPortal.tsx` 本身只提供 portal。

**建议交互**：

- 对真正终止会话的按钮使用“结束会话”，与关闭侧栏项、移除工作区区分。
- 确认内容包含主机、会话名和明确后果：`将终止该会话中的程序，不能撤销`。
- 批量操作展示待结束对象列表，而不只给一个数字；执行中禁用重复确认，完成后说明成功与失败对象。
- 利用已有快照可得到的信息提示窗格或 Agent 状态；无法确认的后台任务不能写成“没有运行任务”。
- 危险弹窗默认聚焦取消或安全位置，Tab 不离开弹窗，Escape 取消，关闭后还原到原触发位置；不要一律把焦点送回终端。

可以提供“先保存终端输出”入口，但必须明确输出归档不是进程快照，无法恢复运行中的程序。**不能给真正终止的会话做虚假的“撤销”按钮。** 文件回收站已支持恢复，继续复用即可。

**验收场景**：双击确认只提交一次；键盘操作不会穿透弹窗进入终端；用户能分清关闭界面与终止 tmux 会话。

### 6. 提示反馈：错误应能处理，成功应尽量安静

**当前依据**：`ToastViewport.tsx` 默认约 2.8 秒自动移除，错误和成功都使用同一计时逻辑，仅显示消息文本。`toasts` 每次变化都会清理并重设所有计时器，因此现有提示的停留时间也会受新通知影响。

**建议交互**：

- 普通成功继续轻提示；频繁切换和自动恢复不刷屏。
- 文件保存、上传或连接失败保留更久，并支持关闭；错误不应只有短暂的一句原始异常。
- 在错误发生处保留上下文和重试入口，例如编辑器内显示 `保存失败，修改仍保留`，而不是只在角落通知。
- 长任务继续使用现有任务中心；Toast 只提示入口，不另做任务系统。
- 有选择地增加辅助技术可感知的提示语义，避免终端高频状态不断打断用户。

重试必须回到具体操作的现有流程；不要把任意副作用请求都统一自动重放。涉及通知结构的新增字段应保持旧调用兼容。

**验收场景**：失败数秒后仍找得到对应对象与恢复动作；连续多个通知不会反复重置旧通知寿命；已保存和保存失败不能呈现相同的短促反馈。

### 7. 历史浏览：告诉用户正在看旧输出，并能回到实时位置

**当前依据**：已有终端滚动、copy-mode 与取消处理；不能按普通聊天窗口直接追加一个自动滚到底部的规则。当前终端组件没有明确的“查看历史 / 返回实时输出”常驻交互入口。

**建议交互**：仅在离开实时位置时显示轻量按钮 `正在查看历史 · 返回实时输出`；有新输出时显示提示点，不强行拉回底部。普通实时输入场景不显示额外按钮。

先辨别浏览的是 xterm 本地滚动还是 tmux copy-mode，再使用现有状态和动作接入。旁观端不能通过返回实时操作改变其他客户端的 tmux 状态；全屏应用不按普通日志流处理。没有可靠的状态来源时先做原型，不增加一套猜测状态。

**验收场景**：持续输出时查看历史不被打断；主动返回后能继续跟随；双端共享、旁观端、Vim 等场景没有交互副作用。

### 8. 空状态与目录跟随：从“说明文字”变成下一步

**当前依据**：`PaneGrid.tsx` 的无会话状态主要提示没有窗口、请选择会话；`FilePanel.tsx` 已有 `followActivePath` 和 `followSuspended`，并非缺少目录跟随能力。

**建议交互**：

- 无主机时提供“添加主机”；有主机但无会话时提供“新建会话”；有会话未选中时提供“选择最近会话”。复用已有入口，不增加强制新手向导。
- 文件路径旁清楚区分 `跟随终端目录`、`已暂停跟随`、`手动浏览`，暂停后提供“恢复跟随”。
- 主机离线、正在加载、没有文件和没有搜索结果使用不同说明，不共用一个空白区域。
- 保留用户当前目录、搜索词和编辑内容；不要以“恢复跟随”为由无提示地切换主机或丢弃修改。

**验收场景**：首次进入、删除最后一个会话、手动浏览后切换窗格，都有明确下一步；正常用户不会被反复引导。

## 三、推荐首批落地范围

优先做五件用户马上能感知、又不需要重构的改动：

1. 旁观与终端就绪状态提示。
2. 设置按钮恢复明确文字，统一底栏选中反馈。
3. 命令面板支持中文动作匹配、选中项自动滚动。
4. 确认弹窗增加执行中反馈和正确焦点行为。
5. 保存等关键失败在操作位置保留恢复入口。

然后再做待发输入管理、移动导航布局试验和历史浏览提示，这些涉及行为语义，回归风险更高。

验证围绕“手机切会话并输入”“双端争用同一会话”“断网恢复”“批量结束会话”“保存失败重试”组织，不以动画数量或新增按钮数量衡量优化。真实 tmux 行为验证必须遵守项目要求，仅操作隔离环境的 `test` session。
