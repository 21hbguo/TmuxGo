# R2 评审产出（review worker → devin %4）

范围：agent-inbox.ts / agent-token.ts / tmux-env.ts / tmux-executor.ts(applyTmuxGoEnv+内联 -e) /
routes/agent-push.ts / routes/inbox.ts / apps/mcp/index.mjs + stream.ts 扇出 + 前端移动端三文件。

## 1. 安全/正确性 findings（严重级 + 修法）

### H1 [高] share ticket 只读观众收到 inbox 全量事件
- `routes/stream.ts:253` `subscribeInbox(e => session.send(e))` 对每个 WS session 无差别扇出；
  `stream-session.ts:282 send()` 不做事件类型过滤。`inbox_message_created` 携带完整 message——
  text 类消息正文、title、route(sessionName/paneId)全部发给 share-link 只读观众。
  同文件 `:251` `agentMonitor.subscribe` 对 share 观众同样无过滤（存量问题，一并修）。
- 修：`const unsubInbox = shareTicket ? null : subscribeInbox(...)`；monitor 事件对 share 按
  白名单（attach/output 类）过滤或同样置 null。

### H2 [高] 敏感路径 denylist 被 symlink 绕过（R1 承诺的 realpath 校验没落）
- `agent-inbox.ts:357-363`：`path.resolve` 只做字符串规整，`stat`/`readFile` 跟随符号链接，
  `isSensitivePath` 检查的是链接名不是目标。`ln -s ~/.ssh/id_rsa ~/x.png` → push x.png
  私钥进 inbox 并下发到全部登录设备。
- 修：`const real = await realpath(resolved)`，对 `real` 再过 `isSensitivePath`（顺手覆盖
  `~` 展开后再逃逸的情况）；或直接 `lstat` 拒绝 isSymbolicLink。同时检查 `info.isFile()` 用
  realpath 后的 stat。

### M3 [中] denylist 覆盖不足
- 缺：`~/.tmuxgo/agent-event-token`（token 本体被推送到 UI 持久化下载）、`~/.claude.json` /
  `~/.claude/`（API key+OAuth）、`~/.codex/auth.json`、`~/.git-credentials`、`~/.config/gh/`、
  `~/.npmrc`(`_authToken`)、`~/.pypirc`、`~/.hermes/config.yaml`（多个 MCP key）、
  `/proc/*/environ`（同 uid 可读任意进程 env，token/密钥直接泄）、`.envrc`
  （`\.env([./]|$)` 不匹配）、`*.pem|*.key|*.p12|*.pfx` 私钥扩展名、`~/.azure`/`~/.config/gcloud`。
- 修：补 SENSITIVE_PATH_PATTERNS + realpath 校验（H2 修复后这些才真正生效）。

### M4 [中] store 损坏 = 静默清空，无备份
- `agent-inbox.ts:137-150`：JSON.parse 失败 → `loaded=null` → 空 store → `saveStore` 立即
  rename 覆盖坏文件。asset 文件还在但索引全丢，无 `.corrupt` 副本无法人工恢复。
- 修：parse 失败时先 `rename(storePath, `${storePath}.corrupt-${Date.now()}`)` 再建空 store；
  或 writeStore 覆盖前 copyFile 留 `agent-inbox.json.bak`（上次好副本）。

### M5 [中] remote/agent host 冷启动首个 pane 拿不到 TMUXGO_* env
- `tmux-executor.ts:82-89` `supportsInlineEnvArgs` 只判 `hostId==='local'`；remote ssh/agent
  host 全走 setenv -g。冷启动（server 不在）：setenv 失败 → defer → create → retry，
  但**首个 pane 在 setenv 生效前诞生**，env 缺失——pane 内 MCP bridge 无 token/URL，
  tools/call 静默报"未配置"。local tmux<3.2 同坑。
- 修：per-host 缓存 `tmux -V` 探测（remote 走 ssh 同通道），≥3.2 同样内联 `-e`；
  <3.2 兜底：create 的 shell-command 位拼 `env K=V ... exec ${SHELL:-sh} -l`，
  保证首 pane 也带 env。

### M6 [中] MCP bridge 异常 → tools/call 永远无响应
- `index.mjs:207` `handleMessage(m).catch(()=>{})` 吞异步异常且不回 JSON-RPC error，client
  挂到自身 timeout；`callGateway` 的 fetch 无 AbortSignal，gateway 挂起同样悬挂；
  无 id 的通知式 tools/call 会回一个**缺 id 的 result**（协议违规）。
- 修：`catch` 里 `replyError(message.id, -32603, err.message)`（id 存在才回）；
  fetch 加 `signal: AbortSignal.timeout(15000)`；handleToolCall 开头
  `if (!('id' in message)) return`。

### M7 [中] base64 上限与 bodyLimit 不自洽，32MiB 实际到不了
- `agent-push.ts:24` bodyLimit=40MB；`agent-inbox.ts:60` MAX_BASE64_BYTES=32MiB **解码后**，
  base64 文本 ≈44.7MB+JSON 开销 > 40MB → 接近上限的合法请求被 fastify 413 先拒。
- 修：bodyLimit 提到 48MB，或 MAX_BASE64_BYTES 降到 ~28MiB 并同步 PROTOCOL.md。

### L8 [低] multipart fields 在 file part 之后到达 → 元数据静默丢
- `agent-push.ts:33-53`：`request.file()` 只取首个 file part，`file.fields` 只含 file **之前**
  的 fields；客户端把 route/source/open 排在 file 后则全部丢弃且返回 200。
- 修：file 消费后继续 `for await (const part of request.parts())` 收剩余 fields；
  或 PROTOCOL.md 写明 fields 必须先序 + 服务端对"fields 疑似丢失"告警。

### L9 [低] markInboxRead：emit 先于落盘 + 批量事件风暴
- `agent-inbox.ts:466-472`：每条消息 emit 一次 `inbox_message_updated`（500 ids → 500 条 WS），
  且 emit 在 `saveStore` 之前——崩溃窗口内前端状态与盘上不一致。
- 修：先 saveStore 再 emit；批量改为聚合事件 `{type, ids[]}` 或对同一 tick 合并广播。

### L10 [低] dedupe map / readBy 无界增长
- `sweepExpired` 逐出消息不清 `value.dedupe` 对应 key（只有 deleteInboxMessages 清）；
  `readBy` 可被任意数量不同 deviceId 灌水（每条 ≤128 字符无上限数）。
- 修：sweep 里 prune 孤儿 dedupe key；`readBy` 超 64 时丢弃最老 deviceId。

### L11 [低] 共享 asset 被配额淘汰 → 其他消息 assetId 悬空
- `agent-inbox.ts:174-185`：两条消息引用同 assetId 时，按消息逐出把 asset 一并删，
  另一条消息保留但 `/inbox/:id/asset` 404。
- 修：淘汰 asset 前检查 `messages.some(m => m.assetId===asset.id && m.id!==victim.id)`，
  被共享则只删消息保 asset（或级联删所有引用者，行为写进文档）。

### L12 [低] sweep 孤儿回收可误删 assetsRoot 下非 asset 文件
- `agent-inbox.ts:188-198`：凡二层文件且文件名不在 liveSha 即 `rm -f`；TMUXGO_DATA_DIR
  指向有杂项的目录时会删用户文件；顶层散落文件反而跳过（readdir 失败）。
- 修：只在 2-hex 目录内删 `^[0-9a-f]{64}$` 文件名；其他一律不动。

### L13 [低] asset.path 以 configDir 为锚，TMUXGO_DATA_DIR 变更后解析断裂
- `agent-inbox.ts:396` 存 `path.relative(configDir(), assetPath)`；DATA_DIR 改动后旧记录
  resolve 到新 assetsRoot 之外 → `resolveAssetPath` 抛 → 500。
- 修：存相对 `assetsRoot()` 的路径；兼容旧记录（含 `inbox-assets/` 前缀则剥掉）。

### L14 [低] x-tmuxgo-env 头只是标记不是边界
- 任何持 token 者都能加该 header；agent-token env>file 的优先级意味着 env 旧 token 会
  永久盖住轮换后的文件 token（直到重启）。文档/注释别把 guard 写成安全边界；
  token 轮换机制（版本化/过期）可以记为 R3+ 待办。

### 核实过无问题（免得重查）
- token：timingSafeEqual + 0600 + atomic rename 链 OK；env→file 回落一致。
- Range：`start<size` + end 钳制 + 416 OK；不支持 suffix `bytes=-500`（走 200 全量，可接受，
  要补就在 RANGE_RE 加 `(\d*)-(\d+)` 分支）。
- find-my-way 静态优先：`/inbox/unread-count` 不会被 `/:id` 抢。
- Origin hook 在最前且无 Origin 放行 → curl/bridge 正常；cookie-auth POST 有 Origin 拦截。
- store 写：tmp+rename+0600 原子；savePromise 串行且写同一可变对象 → 后写覆盖最新态，无丢写。
- `isTmuxGoEnvArg` 是死导出（无调用点），删掉或留作 R3 用。
- createPush dedupe 并发窗：两个并发同 key push 都会新建（check 与 set 之间有 await），
  影响只是重复消息，低危——要严格就在 dedupe check→set 间去掉 await（把 asset 写盘挪到
  标记 key 之后）。

## 2. Agent 启动集成：「新建 session → 选 agent 模板 → 自动 MCP+env」

### 各 CLI 注入方式（本机实证）
| CLI | 配置位置 | 注入手段 | 备注 |
|---|---|---|---|
| codex | `~/.codex/config.toml` `[mcp_servers.tmuxgo] type="stdio" command="node" args=[abs]` | `codex mcp add tmuxgo -- node <abs>`（幂等需先 `mcp get` 判断）/直接 merge toml | 本机已配；stdio 子进程继承 codex env → pane TMUXGO_* 自动进入；`-c` 单次 override 太啰嗦不推荐 |
| claude-code | user `~/.claude.json` mcpServers / project `<cwd>/.mcp.json` / local | `claude mcp add -s user tmuxgo -- node <abs>` / JSON merge | 本仓 `.mcp.json` 已 commit(100f0a3)：cwd=repo 的 pane 信任后自动生效；非 repo cwd 只能 user scope |
| dsh | profile `cordis.patch.yml` 追加 plugin 条目 | `- id: mcp-tmuxgo` `name: '@deepseek-ai/dsh-mcp-client'` `config: {serverName: tmuxgo, transport: stdio, command: node, args:[abs]}` | **或** `dsh --profile <p> --patch <file.yml>` 启动期 overlay——零侵入 profile，最适合模板化 |
| hermes | `~/.hermes/config.yaml` `mcp_servers.tmuxgo: {command: node, args:[abs], enabled: true}` | YAML merge；`inherit_mcp_toolsets: true` 已在 | 注意 `hermes codex-runtime migrate` 会重写 codex config.toml 托管块——tmuxgo 条目放托管块外即可 |

### 可落地方案（R3 直接做）
1. **env 链路已闭环**：bridge 从 `TMUXGO_AGENT_EVENT_TOKEN`/`TMUXGO_GATEWAY_URL`/`TMUX_PANE` 自取，
   无需 per-agent 额外 env。模板只需再补 `TMUXGO_AGENT_NAME=<kind>`、`TMUXGO_AGENT_SESSION_ID=<uuid>`
   （index.mjs sourceInfo 已读）→ `getTmuxEnvEntries(hostId, agent?)` 加可选参数拼进内联 `-e`。
2. **模板 schema**：`SessionTemplateLayout.panes[]` 加 `agent?: {kind:'codex'|'claude'|'dsh'|'hermes', command?: string, profile?: string}`；
   启动命令走 new-session/split-window 的 shell-command 位（`codex` / `claude` /
   `dsh --profile <p> --patch <gen>` / `hermes chat`），cwd 沿用 pane.cwd。
3. **幂等 MCP provision**（gateway，一次性，结果记 `~/.tmuxgo/mcp-provisioned.json` + 文件锁）：
   - codex：`codex mcp get tmuxgo` 不存在才 `codex mcp add`；CLI 缺席时 merge config.toml。
   - claude-code：merge `~/.claude.json` `mcpServers.tmuxgo`（JSON 直写，不依赖 CLI）；repo 内靠 `.mcp.json`。
   - dsh：gateway 生成固定 `~/.tmuxgo/dsh-tmuxgo-mcp.patch.yml`（上面那段 plugin 条目），模板命令
     恒带 `--patch`——不碰用户 profile。
   - hermes：merge `config.yaml` `mcp_servers.tmuxgo`。
   provision 失败降级 toast，不阻塞 session 创建。
4. **交互**：CreateSessionDialog 模板选择处加 agent 下拉（或模板内置）；`POST /hosts/:hostId/sessions`
   收到 layout 含 agent 时先 `ensureMcpProvisioned(kind)` 再建 pane。
5. **边界（写明别再做）**：MCP 注册是全局单文件（codex/hermes）→ pane 级隔离不做，归属靠
   `TMUX_PANE`+`TMUXGO_AGENT_NAME`；dsh streamable-http transport 也可用但 stdio 已够；
   remote host 的 MCP 注册在其本机配置——模板只可声明"远端需自行预置"（或后续 agent-ws 反向下发）。

## 3. 移动端代码级痛点（文件 + 位置 + 改法）

1. **MobileDrawer.tsx:465-473**：下拉关闭手势只绑在 ~24px 高的把手条上；列表滚到顶后下拉
   抽屉不响应（iOS 习惯是内容到顶继续下拉就关 sheet）。修：touchstart/move 挂到 panel 容器，
   move 时判 scroll 容器 `scrollTop<=0 && dy>0` 才 translateY；把手区保持现状。
2. **MobileDrawer.tsx:355-370 `handleSelectPane`**：串行 `await select-window → select-pane →
   snapshot.get` 三个 RTT 后才 `handleClose`——弱网抽屉停住无反馈，用户重复点造成重复调用。
   修：点击即 `setActivePane`+`handleClose` 乐观关闭，API 链后台跑，失败 toast（顺序约束保留）。
3. **TerminalPane.tsx:509-517 `onTouchEnd`**：移动端任何未移动 tap 一律 `preventDefault` +
   `dispatchTerminalTap` + `focusKeyboard`——点链接/浮层外区域都会强弹键盘遮半屏。
   修：tap 后延迟 ~300ms 再 focus（期间若发生 scroll/二次手势则取消），或键盘唤起改为
   显式按钮/长按；至少加 preferences 开关 `tapToKeyboard`。
4. **useTerminalTouchScroll.ts:258-262, 316-330**：垂直滚动每 ~18px 发一条 `pane_scroll` WS；
   fling 后 momentum 用 `setTimeout(16)` 每帧再发——快速滑动产生 ~60msg/s 上行 flood，
   弱网关队列积压画面滞后。修：行数累积 + 80ms 节流合并单条发送；momentum 换 rAF。
5. **SessionPanel.tsx:386-389 + 466-509**（粗指针端= iPad/触屏本）：`TouchSensor{delay:220,
   tolerance:8}` 长按拖排与列表滚动/长按菜单抢手势；操作钮 `h-7 w-7`(28px)、批量 ☐ `h-7 w-5`
   均低于 44px 触控目标，删 × 与 rename ✎ 相邻易误触。修：coarse pointer 下 sortable 仅在
   专用拖柄激活（或移动端直接禁用 TouchSensor 走 MobileDrawer）；行操作钮升到 ≥36px 并拉开间距。
