## 1. Inbox overlay/back 栈（P0-3）

- `pushOverlay` 约 172-177 行：保持现有“入栈 + `history.pushState`”唯一入口；新增 `openInbox`/`openInboxPreview` 时分别压入 `inbox`、`inbox-preview`，不要直接 `setState(true)` 而跳过 history。
- `closeOverlay` 约 179-190 行：沿用 `lastIndexOf` 和 backCount，不新增第二套关闭逻辑。
- `handlePopState` 约 572-610 行：在 `top` 分支中加入：
  - `inbox-preview` → 关闭 preview，不关闭 inbox；
  - `inbox` → 关闭 inbox；
  - `mobile-files-level`/`mobile-git-level` 分支保持原行为。
  - 分支结束仍只 `stack.pop()` 一次；如果 preview 子组件已消费 back，必须按现有 `detail.handled` 约定 return，避免双 pop。
- 移动 dock 约 785-804 行：向 `MobileNav` 传 `inboxOpen`、`inboxUnread` 和 `onOpenInbox`；键盘打开时沿用 `ShortcutBar`，不要在键盘态渲染 inbox sheet。

- route 跳转 callback：收到 `inbox_open_target` 后先 `setActiveSession`，再由 inbox 目标组件调用 `MobileDrawer` 同一条 pane 选择链；不要从 ConsoleLayout 直接调用未封装的 tmux API。

### worktree B 验收

- 再 back：只关 Inbox。
- Inbox 打开后切 session/pane，再 back：不退出页面；overlay stack 无残留。
- 根页面 back 仍使用现有“双击退出提示”，不能改变 `stack.length === 0` 分支。

## 3. 推送路由到 pane 的真实链路（P0-4）

### 现有可复用链路

- `apps/frontend/src/components/MobileDrawer.tsx` `handleSelectPane` 约 355-369 行：这是唯一正确的跨 window 顺序：先 `api.windows.select`（约 360-361），再 `api.panes.select`（362），重新取 snapshot 并写 query cache（363-365），最后 `setActivePane`（365），然后 `handleClose`（369）。
- `apps/frontend/src/components/PaneGrid.tsx` `switchPane` 约 256-284 行：同样先 `setActivePane(next.id)`，再 `api.panes.select(next.id, { keepZoom })`，成功后 invalidate snapshot。Inbox 不要复制此逻辑，只调用一个已暴露的导航 callback/复用 MobileDrawer 选择函数。
- `useConsoleStore.setActivePane` 当前是本地 active pane 标记；它不是 tmux 选择 API，不能只调用它就宣称完成跳转。

### worktree B 具体做法

1. 在 `MobileDrawer` 抽出或暴露“按 paneId 选择”最小复用入口（若抽函数会造成跨组件复杂化，则把 inbox target 转成打开 `MobileDrawer(type='panes')` 并通过现有 `activePaneId`/目标高亮完成一次用户点击，不要直接复制 API 调用）。
2. 推荐实现是给 `MobileDrawer` 增加 `initialPaneId?: string` 或 `focusPaneId?: string`：打开 panes 时定位目标并执行同一 `handleSelectPane`，跨 window 仍严格按 360-365 顺序。
3. route 缺少 `sessionName`/`paneId` 或找不到目标时，留在 Inbox 并 toast “目标 pane 不存在”，不能把 active session 清成空。
4. 跳转成功后再 `closeOverlay('inbox-preview')`/`closeOverlay('inbox')`，顺序不能反过来，否则异步选择尚未完成时 UI 会卸载目标组件。

### 测试

- 从另一个 window 的 inbox message 跳 pane：断言 `windows.select` 在 `panes.select` 之前。
- `setActivePane` 与 snapshot 更新都发生；API 失败时保持 Inbox 可见并显示错误。
- route 只有 `tmuxPaneId` 时先按当前 host/session 查找，查不到进入全局 inbox，不误选相同 `%N` 的其他 host。

## 4. 键盘/viewport与媒体预览（P0-2）

### `ConsoleLayout.tsx`

- 复用现有 `appHeight`、`visualViewport`、`keyboardStateRef`、`scheduleViewportSync`；Inbox sheet 和 preview 以父 shell 的 `appHeight` 布局，禁止使用固定 `100vh`。
- sheet 样式沿用 `env(safe-area-inset-bottom)`；键盘打开 (`keyboardOpen`) 时不自动 focus 搜索框/文本输入，打开预览不改变 terminal fit。
- 只在 preview 内做媒体 lazy load；图片使用 `loading="lazy"`，视频不 autoplay，组件卸载 `AbortController`/撤销 object URL。
- 不改 `PaneGrid` 的 resize debounce、输入队列和 attach 常量；inbox 性能问题不能通过降低 terminal resize 可靠性解决。

## 5. 不要改动的边界

- 不把 Inbox state 加入 `useConsoleStore`；使用独立 `useInboxStore`，移动端只持久化 messageId/tab 元数据。
- 不在 `MobileNav` 内请求 API；数据由 hook/store 提供。
- 不从 WS 推 blob/base64；WS 只发 metadata，preview 走 REST。
- 不修改 `PaneGrid` 的 tmux 输入、resize、attach 逻辑；只接收导航 callback。
